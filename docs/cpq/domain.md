# CPQ 业务领域术语与规则

> 仓库上下文文档。上游需求：`docs/FastAdmin-CPQ开发功能与实施方案.md`（§2、§4、§12）。
> 后续每次开发任务开始前必读本文；与总方案冲突时以总方案为准并同步修订本文。

## 1. 业务定位

制造业通用 CPQ（Configure-Price-Quote）：销售在受控的产品配置模型上完成选配，
系统按确定性规则校验配置、计算价格、生成报价并走固定审批流，最终产出 PDF 报价单。

第一阶段 MVP 范围：产品主数据与配置模型、配置规则、BOM 映射、价格表与价格规则、
报价草稿/版本/审批/PDF/审计。不做：合同管理、CAD 可视化、ERP 库存、经销商门户、双向深度集成。

## 2. 角色与数据权限

| 角色编码 | 角色名称 | 主要权限 | 数据范围 |
| --- | --- | --- | --- |
| `sales` | 报价销售 | 新建配置、试算、提交报价 | 本人或所属销售组织 |
| `sales_manager` | 销售经理 | 查看团队报价、审核一般折扣 | 所属销售组织及下级 |
| `product_manager` | 产品经理 | 产品型号、选项、BOM、配置规则 | 指定产品线 |
| `line_pricer` | 产线价格管理员 | 维护产线价格、审批产线控制价区间 | 指定产品线 |
| `company_pricer` | 公司价格管理员 | 维护公司控制价、公司级特批 | 全公司 |
| `finance_reviewer` | 财务审核 | 成本、毛利、税率、付款条件审核 | 被分配单据 |
| `master_data_admin` | 主数据管理员 | 客户、地区、币种、组织、字典维护 | 全公司 |
| `auditor` | 审计员 | 只读查看报价、版本、审批和日志 | 全公司，只读 |
| `system_admin` | 系统管理员 | 用户、角色、参数、接口和任务管理 | 系统级 |

### 2.1 权限铁律（服务端必须重复校验，不能只靠前端隐藏）

1. 销售人员不能查看公司控制价和完整成本，只能看到允许公开的价格及利润结果等级；
2. 审批人不能修改待审批报价，只能批准、驳回或要求修改；
3. 报价创建人与最终特批人不得为同一人；
4. 已发布的产品规则和价格版本不得直接修改，只能复制产生新版本；
5. 已批准报价不得覆盖编辑，只能创建修订版本；
6. 导出、批量下载、查看成本及控制价均写入审计日志。

## 3. 核心领域概念

| 术语 | 含义 | 关键规则 |
| --- | --- | --- |
| 产品系列 | 型号的业务分组（业务板块/产品线维度） | 有唯一编码，草稿/发布状态 |
| 产品型号 | 可报价的最小产品单元 | 携带基础物料编码、单位、参数与配置结构 |
| 技术参数 | 型号的描述性参数（功率、材质等） | 区分"可配置参数"与"展示参数" |
| 配置组 | 一类配置选择的容器 | input_type：single/multiple/number/text/readonly；单选/多选带必选、min/max |
| 配置选项 | 配置组内的可选值 | 携带物料编码与默认数量，参与 BOM 展开 |
| 配置规则 | 受控 DSL 表达的依赖/互斥/数量/公式规则 | REQUIRES、EXCLUDES、ONE_OF、MIN_MAX、FORMULA、WARNING；禁止 eval |
| 配置模板 | 面向市场范围的推荐配置 | 复制为起点，不直接锁定 |
| BOM 映射 | 选项/型号 → 物料 + 数量公式 + 损耗率 | 存在已发布映射时按映射生成 BOM，否则按选项物料直出 |
| 价格表 | 型号/选项的价格容器（公司/范围/币种/税制/版本） | 发布后不可改，只能新版本 |
| 三层控制价 | 指导价 guide_price / 产线底线 line_floor / 公司底线 company_floor | 低于哪层进入对应审批层级；低于公司底线禁止提交 |
| 价格规则 | 条件→调整（折扣/加价/一口价） | 优先级 + 维度具体度匹配，冲突时阻止报价而非猜测 |
| 价格轨迹 | 每一步价格计算的输入/规则/输出记录 | 写入 `price_trace_json`，按权限裁剪可见性 |
| 报价 | 面向客户的正式商务文档 | 主表 + 版本（revision）+ 行 + 配置快照 + 价格快照 + 条款快照 |
| 报价版本 | 报价的不可变修订 | `quote_id + revision_no` 唯一；已批准报价修订产生新版本 |
| 配置哈希 | 规范化配置 JSON 的 SHA-256 | 等价配置（键序/数值格式不同）必须同哈希 |
| 审批实例/任务 | 固定状态机的审批流载体 | 动作携带版本号与幂等键；旧版本任务自动失效 |

## 4. 关键业务流程

### 4.1 配置校验（`ConfigurationService`，已实现）

处理顺序固定：校验型号与规则版本 → 标准化输入并移除未知字段 → 计算可见性与默认值 →
执行依赖/互斥/数量规则 → 执行受控公式 → 检查必选完整性 → 生成 BOM →
输出稳定排序后的配置 JSON 与 SHA-256 哈希。

### 4.2 价格流水线（`PricingService`，M2 实现）

```text
型号基础价 + 选项增量价 + 配件/服务价
→ 适用价格规则 → 数量调整 → 客户/代理/区域调整 → 手工折扣
→ + 运费/保险/安装等费用 → 未税金额 → + 税额 → 含税总额
→ 汇率换算与金额舍入 → 三层控制价比较 → 审批等级
```

策略匹配从最具体到最通用：指定客户 → 指定代理商 → 等级+区域 → 等级 → 区域 →
国内/国际 → 产品线默认 → 公司默认。相同具体度取高优先级；仍冲突返回"规则冲突"并阻止提交。

### 4.3 报价向导（六步，M2 实现）

基本信息 → 选择产品 → 产品配置器 → 价格与折扣 → 商务条款 → 预览与提交。

### 4.4 报价审批（M3 实现）

固定状态机（见 `state-machines.md`），审批动作与任务状态迁移必须在同一事务内。

## 5. 通用技术约定（业务侧）

- 金额一律 `DECIMAL(18,4)` + Money/Decimal 值对象，禁止 float 计算金额；
- 汇率 `DECIMAL(18,8)`、比例 `DECIMAL(9,6)`；
- 日期统一保存 UTC，页面按 Asia/Shanghai 显示；
- 演示/测试数据统一 `CPQ-DEMO` 前缀，不使用真实客户、物料或价格；
- 业务表逻辑名 `cpq_` 前缀，物理表 `fa_cpq_*`（跟随 FastAdmin 数据库前缀）。
