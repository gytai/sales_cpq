# 基于 FastAdmin 的制造业通用 CPQ 开发功能与实施方案

版本：V1.1  
编制日期：2026-09-03  
适用范围：制造业通用产品配置、定价、报价、报价审批、报价输出及基础系统集成；可适配包括美亚光电在内的装备制造企业  
项目边界：合同及合同预审不属于本次 MVP

> [!important]
> 本文既是产品功能规格，也是供 AI 辅助开发使用的技术实施说明。AI 开发时必须按“数据模型 → 服务层 → API → 页面 → 测试”的顺序逐项实现，不得根据页面效果反推或临时拼接核心业务规则。

## 1. 项目结论

当前仓库中的 FastAdmin 可以作为制造业通用 CPQ 的后台与基础权限框架，但它不是现成 CPQ。项目需要在现有代码结构内自行开发产品配置规则引擎、定价引擎、报价版本、报价审批和审计留痕。

推荐定位：

- FastAdmin：后台菜单、登录、角色权限、基础 CRUD、数据导入导出；
- CPQ 业务模块：在 `application` 和 `public/assets` 的既有扩展位置开发，与 FastAdmin/ThinkPHP 核心代码隔离；
- 产品配置器：MVP 使用 FastAdmin 原生后台页面、Bootstrap、jQuery、RequireJS 和 Form 组件实现；
- 服务端：沿用 ThinkPHP 5/FastAdmin 的 Controller、Model、Validate 机制，复杂业务逻辑下沉到 CPQ Service；
- 数据库：MySQL；
- 缓存与异步任务：Redis；
- 部署方式：Docker Compose 私有化部署。

### 1.1 建设目标

系统必须解决以下问题：

1. 根据业务板块、国内/国际、地区、产品线、代理商等级形成不同价格体系；
2. 支持按产品系列、型号、配置组、配置项、技术参数、配件和服务灵活定义可销售产品结构，不绑定某一种设备或行业专用属性；
3. 自动校验必选、依赖、互斥、数量和兼容性规则，输出合法配置和 BOM；
4. 按官方指导价、产线控制价、公司控制价校验报价和利润；
5. 根据最低价格层级自动进入销售、产线或公司审批；
6. 对报价创建、修改、审批和输出过程记录人员、时间、内容和版本；
7. 输出中英文、CNY/USD 等多币种正式报价单；
8. 预留标准 API 与 CRM、ERP 等外围系统交换主数据和报价结果。

### 1.2 第一阶段不做的内容

为了控制两个月 MVP 范围，以下功能不进入第一阶段：

- 合同管理、合同预审、合同条款库及合同系统集成；
- 三维设备建模、CAD 在线渲染；
- 自动生成生产工艺路线；
- 库存预占和采购计划；
- 在线支付和电子发票；
- 经销商对外开放门户；
- AI 自动决定价格或自动批准低价；
- 与真实生产 ERP 的双向实时写入。

AI 可以辅助检索产品、解释规则、生成报价说明，但不得绕过确定性规则引擎和审批权限。

### 1.3 当前代码基线与实施约束

本方案以仓库当前代码为唯一技术基线，不另起一套前后端框架：

| 项目 | 当前基线 | MVP 实施方式 |
| --- | --- | --- |
| 后端框架 | FastAdmin `1.6.5.20260602`、ThinkPHP `5.0.28` | CPQ 后台 Controller 继承 `app\common\controller\Backend`，API Controller 继承 `app\common\controller\Api` |
| PHP | `composer.json` 要求 PHP `>= 7.4` | 先在 M0 锁定实际部署版本并完成兼容性与安全验证 |
| 后台前端 | Bootstrap 3、jQuery、RequireJS、Bootstrap Table、FastAdmin Form | 页面放入 `application/admin/view/cpq/`，脚本放入 `public/assets/js/backend/cpq/` |
| 数据访问 | ThinkPHP Model、`think\Db`、事务 | 单表 CRUD 沿用框架，跨表配置、定价、审批由 Service 编排 |
| 输入校验 | ThinkPHP Validate、FastAdmin 表单校验 | 前端即时提示，后端 Validate 与 Service 重复校验业务边界 |
| 权限与日志 | FastAdmin RBAC、数据权限、后台操作日志 | 复用登录和菜单权限，新增产品线/销售组织/区域数据范围校验及 CPQ 业务审计 |
| 前端扩展 | 当前仓库没有 Vue 工程 | MVP 不引入 Vue、React 或独立 SPA；确需重构配置器时作为后续独立决策 |
| 数据库变更 | 当前仓库没有业务 migration 目录 | 新增 `database/cpq/` 管理安装 SQL、增量升级 SQL 和演示数据，不修改框架安装 SQL |

### 1.4 MVP 范围

| 范围内 | 范围外 |
| --- | --- |
| 产品主数据与通用配置模型 | 合同、合同预审和合同条款管理 |
| 配置规则校验与 BOM 映射 | CAD/三维可视化和生产工艺设计 |
| 价格表、价格规则与价格试算 | ERP 库存预占、采购和生产计划 |

| CRM/ERP 基础接口预留和手工导入导出 | CRM/ERP 双向实时深度集成 |

## 2. 用户角色与数据权限

| 角色编码 | 角色名称 | 主要权限 | 数据范围 |
| --- | --- | --- | --- |
| `sales` | 报价销售 | 新建配置、试算、提交报价 | 本人或所属销售组织 |
| `sales_manager` | 销售经理 | 查看团队报价、审核一般折扣 | 所属销售组织及下级 |
| `product_manager` | 产品经理 | 产品型号、选项、BOM、配置规则 | 指定产品线 |
| `line_pricer` | 产线价格管理员 | 维护产线价格、审批产线控制价区间 | 指定产品线 |
| `company_pricer` | 公司价格管理员 | 维护公司控制价、公司级特批 | 全公司 |
| `finance_reviewer` | 财务审核 | 成本、毛利、税率、付款条件审核 | 被分配单据 |
| `master_data_admin` | 主数据管理员 | 客户、地区、币种、组织、字典维护 | 全公司 |
| `auditor` | 审计员 | 只读查看报价、版本、审批和日志 | 全公司，只读 |
| `system_admin` | 系统管理员 | 用户、角色、参数、接口和任务管理 | 系统级 |

### 2.1 权限原则

- 销售人员不能查看公司控制价和完整成本，只能看到允许公开的价格及利润结果等级；
- 审批人不能修改待审批报价，只能批准、驳回或要求修改；
- 报价创建人与最终特批人不得为同一人；
- 已发布的产品规则和价格版本不得直接修改，只能复制产生新版本；
- 已批准报价不得覆盖编辑，只能创建修订版本；
- 所有服务端 API 必须重复校验角色和数据范围，不能只依赖前端按钮隐藏；
- 导出、批量下载、查看成本及控制价均写入审计日志。

## 4. 页面级功能规格

## 4.1 工作台

### P01 CPQ 驾驶舱

**入口**：工作台 → CPQ 驾驶舱  
**角色**：销售、销售经理、价格管理员、系统管理员  
**目标**：展示报价业务整体状态，并提供高频操作入口。

**页面模块**：

1. 指标卡片：本月新建报价、待审批、已批准、已驳回、即将过期、预计金额；
2. 报价漏斗：草稿、审批中、已批准、已发送、客户接受、已失效；
3. 价格风险：需产线审批、需公司审批、低于公司控制价、缺少价格策略；
4. 趋势图：近 12 个月报价金额、批准率、平均折扣率；
5. 产品分布：按业务板块、产品线、产品系列和型号统计，可由字典和主数据动态扩展；
6. 待办列表：单号、客户、产品线、金额、当前节点、停留时间；
7. 快捷入口：新建报价、价格试算、复制历史报价、导入客户。

**筛选条件**：公司、销售组织、产品线、销售区域、币种、时间范围。  
**数据权限**：按当前用户角色和组织范围聚合，不得泄露无权限报价金额。  
**验收标准**：指标点击后进入对应列表，并自动带入完全相同的筛选条件。

### P02 我的待办

**入口**：工作台 → 我的待办  
**角色**：全部业务角色

**功能**：

- 按待处理、已处理、我发起的、抄送我的分类；
- 显示业务类型、单号、客户、提交人、到达时间、剩余 SLA；
- 支持产品线、审批类型、紧急程度筛选；
- 支持单条进入、批量转交和添加关注；
- 批量批准默认禁用，仅在规则允许且风险等级相同时开放；
- 超时任务红色提示并通知上级或管理员。

## 4.2 产品中心

### P10 产品系列列表

**入口**：产品中心 → 产品系列  
**角色**：产品经理、主数据管理员

**列表字段**：系列编码、中文名称、英文名称、业务板块、产品线、国内/国际、状态、当前发布版本、更新人、更新时间。  
**操作**：新增、编辑草稿、复制、停用、查看版本、导入、导出。  
**校验**：编码全局唯一；被报价引用后不能物理删除；停用不影响历史报价。

### P11 产品系列详情

**页签**：基本信息、适用市场、型号、配置结构、附件、版本记录。

**基本字段**：

- 系列编码、中文名称、英文名称；
- 业务板块、产品线、品牌；
- 产品说明、默认单位、默认币种；
- 生效日期、失效日期、状态；
- 产品图片、彩页、技术资料。

**操作**：保存草稿、提交发布、复制新版本、停用。  
**发布校验**：至少包含一个有效型号；每个型号存在基础价格或明确标记为询价；所有必选配置组均有有效选项。

### P12 产品型号列表

**列表字段**：型号编码、系列、型号名称、产品分类、计量单位、基础物料、默认 BOM、配置模板、状态、版本。  
**操作**：新增、复制型号、编辑、发布、停用、配置预览、查看引用报价。

### P13 产品型号详情

**页签**：基本信息、技术参数、配置项、默认配置、BOM、价格、规则、附件、版本。

**核心字段**：

- 型号编码、系列、产品线、中文/英文名称；
- 由参数模板定义的结构化技术参数；参数名称、类型、单位、是否必填和可选值均可配置；
- 默认配置模板、基础物料编码、计量单位；
- 是否允许销售自定义、是否允许海外销售；
- 生效区间、发布状态。

**功能**：

- 拖拽排列配置组；
- 设置每组单选、多选、数量、文本或数值类型；
- 设置默认选项和销售是否可见；
- 一键进入配置预览，验证默认配置是否合法；
- 查看该型号关联的有效配置规则和价格覆盖情况。

### P14 配置项列表

**定义**：配置项是产品选型时可选择或填写的通用维度，例如规格等级、材质、电气制式、性能参数、功能模块、软件授权、配套件或服务。配置项由业务维护，不在代码中固化行业专有字段。

**列表字段**：配置组编码、名称、类型、适用产品线、是否必选、最小/最大选择数、排序、状态。  
**操作**：新增、复制、编辑、停用、查看选项。

### P15 配置项详情及选项维护

**配置组字段**：

- 组编码、中文/英文名称；
- 控件类型：单选、多选、数字、文本、只读计算值；
- 必选、最少/最多选择数；
- 是否影响价格、BOM、交期、重量；
- 可见条件、帮助说明、排序。

**选项字段**：

- 选项编码、名称、物料编码；
- 默认数量、数量上下限、步长；
- 增量价格、增量成本的引用键；
- 图片、说明、技术参数；
- 生效区间、状态。

**页面功能**：选项新增、批量导入、拖动排序、默认值设置、被引用检查、影响分析。  
**校验**：停用选项前必须列出受影响的在售型号、模板和规则。

### P16 配件与服务

**目标**：维护可以独立加入报价、但不一定属于主机配置树的配件和服务。

**列表字段**：编码、类型、名称、单位、适用产品线、默认税类、是否库存物料、状态。  
**类型**：配件、备件、耗材、软件、安装、调试、培训、质保延长、运输及其他；类型通过字典扩展。  
**功能**：维护销售说明、成本引用、价格引用、适用市场、默认数量、附件。

### P17 配置规则列表

**列表字段**：规则编码、名称、规则类型、适用型号、优先级、严重级别、版本、状态、生效日期。  
**规则类型**：

- `REQUIRES`：选择 A 必须选择 B；
- `EXCLUDES`：选择 A 禁止选择 B；
- `ONE_OF`：一组中必须选择一个；
- `MIN_MAX`：数量或数值范围；
- `VISIBILITY`：满足条件才显示配置项；
- `DEFAULT`：满足条件时自动带出默认值；
- `FORMULA`：根据其他选项计算数量或参数；
- `WARNING`：允许继续，但必须展示警告并留痕。

**操作**：新增、复制、测试、提交发布、停用、影响分析、查看版本差异。

### P18 配置规则编辑器

**页面布局**：左侧条件、中央逻辑、右侧结果，下方测试区。

**字段**：

- 规则编码、名称、说明、适用范围；
- 条件组，支持 `AND`、`OR`，不支持任意脚本；
- 条件字段、比较符、比较值；
- 动作类型、目标配置项、目标值、错误信息；
- 优先级、严重级别、生效日期、版本。

**功能**：

- 可视化添加条件和动作；
- 实时显示结构化 JSON；
- 输入一组配置进行单规则测试；
- 批量回放历史配置，检查新规则是否导致历史配置失效；
- 发布前检查循环依赖、永真冲突和不可达选项。

**安全约束**：规则只保存受控 JSON DSL，后端使用白名单解释器执行，严禁 PHP `eval`、JavaScript `eval` 或直接执行数据库表达式。

**规则示例**：

```json
{
  "when": {
    "all": [
      {"field": "parameter.power_level", "operator": "=", "value": "high"},
      {"field": "option.ambient_temperature", "operator": ">", "value": 40}
    ]
  },
  "then": [
    {"action": "require", "target": "option.cooling_level", "value": "enhanced"}
  ],
  "message": "高功率且高温环境使用时必须配置增强散热方案"
}
```

### P19 配置模板列表与详情

**用途**：维护不同应用场景、市场或客户等级的推荐配置，例如“标准配置”“高温环境配置”“经销商演示配置”。

**字段**：模板编码、名称、型号、市场、客户等级、默认配置、推荐说明、版本、状态。  
**功能**：从合法配置保存为模板、复制模板、配置验证、设置型号默认模板、查看使用次数。  
**校验**：模板发布时必须通过当前有效规则全集校验。

### P20 BOM 映射

**目标**：把销售配置转换成 ERP 可识别的物料清单。

**页面内容**：

- 左侧显示产品配置树；
- 右侧显示物料编码、数量公式、单位、替代料、损耗率；
- 下方实时生成模拟 BOM 和错误信息。

**功能**：设置基础 BOM、配置增量 BOM、数量公式、替代料优先级；导入 ERP 物料；模拟生成；版本发布。  
**校验**：每个影响 BOM 的已发布选项必须有有效映射或明确标记“不产生物料”。

## 4.3 价格中心

### P30 价格表列表

**列表字段**：价格表编码、名称、公司、业务板块、国内/国际、币种、含税方式、版本、状态、生效区间。  
**操作**：新增、复制、编辑草稿、提交审批、发布、失效、导入、导出、查看覆盖率。  
**校验**：同一适用范围内不允许存在优先级相同且时间重叠的已发布价格表。

### P31 价格表详情

**页签**：基本信息、适用范围、型号基础价、选项增量价、配件服务价、版本、审批记录。

**功能**：

- 按型号或配置项批量维护价格；
- 从 Excel 导入并预校验；
- 与上一版本对比涨跌金额和比例；
- 检查在售产品价格覆盖率；
- 保存草稿、送审、发布；
- 发布后生成不可变价格版本。

### P32 产品价格矩阵

**目标**：按业务维度查看和维护最终可匹配价格。

**筛选维度**：公司、板块、国内/国际、区域、产品线、客户等级、代理等级、客户、型号、选项、币种、单位、生效日期。  
**表格字段**：维度组合、指导价、产线控制价、公司控制价、成本、币种、税模式、版本、生效期。  
**操作**：新增、批量编辑草稿、导入、导出、复制到新区域、查看冲突和缺口。  
**校验**：`指导价 >= 产线控制价 >= 公司控制价 >= 0`；金额使用 Decimal，禁止浮点数计算。

### P33 价格规则列表

**用途**：在价格表基础上按条件进行加价、减价、折扣或取固定值。

**规则字段**：

- 规则编码、名称、适用范围、优先级；
- 客户、客户等级、代理等级、区域、产品线、型号；
- 最小数量、最大数量、日期区间；
- 调整类型：固定价、加减金额、折扣率、系数；
- 调整对象：基础价、选项价、服务价、运费；
- 是否可叠加、互斥组、封顶/保底限制；
- 版本和发布状态。

**操作**：新增、复制、规则模拟、冲突检测、发布、失效。  
**校验**：同一互斥组最多命中一条；优先级相同且条件重叠时禁止发布。

### P34 成本与控制价

**角色**：产线价格管理员、公司价格管理员、财务，销售不可访问完整数据。

**页面功能**：

- 维护标准成本、最新成本、公司控制价、产线控制价、指导价；
- 批量导入成本变化；
- 查看毛利率和三层价格关系；
- 价格异常提示；
- 变更原因和附件；
- 双人复核后发布。

**敏感控制**：接口响应必须根据角色删除无权字段，而不是只在前端隐藏列。

### P35 汇率、税率与费用

**页签**：汇率、税率、运输费、保险费、安装调试费、其他费用。

**功能**：

- 维护币种、汇率来源、生效日期；
- 税率按国家/地区和产品类型配置；
- 运费支持固定金额、按数量、按重量、按报价金额比例；
- 设置费用是否计入价格控制和毛利计算；
- 手工调整必须填写理由。

**规则**：报价保存价格快照后，汇率更新不得改变历史报价。

### P36 价格模拟器

**输入**：日期、客户、区域、代理等级、币种、型号、配置、数量、折扣、税费。  
**输出**：

- 基础价、选项价、服务价、运费、税额和总价；
- 命中的每条价格规则、执行顺序和调整结果；
- 指导价、控制价比较结果；
- 成本、毛利额、毛利率；
- 所需审批级别；
- 未命中价格或规则冲突。

**功能**：试算、保存测试用例、导出执行轨迹、从试算创建报价。  
**验收标准**：相同输入、相同规则版本必须得到完全相同的结果。

### P37 价格版本发布

**列表字段**：版本号、价格表、变更摘要、影响产品数、影响客户数、提交人、审批人、计划生效时间、状态。  
**功能**：版本差异、影响分析、审批、定时发布、撤回未生效版本、紧急失效。  
**限制**：已生效版本不能修改；回滚通过重新发布旧内容的新版本实现。

## 4.4 客户与渠道

**功能**：新增、编辑、停用、合并重复客户、导入、导出、查看历史报价。  
**校验**：客户等级和销售区域由主数据管理员确认，销售不能在报价中随意覆盖。

### P41 客户详情

**关键字段**：统一信用代码、国家/地区、销售区域、客户等级、代理等级、默认币种、税号、付款条件、贸易条款、销售组织、负责人。  
**功能**：维护客户专属价格规则、查看有效期和审批记录、CRM 同步状态。

### P42 客户等级

**字段**：等级编码、名称、排序、默认折扣、适用市场、状态。

### P43 代理商列表与详情

**字段**：代理商编码、关联客户、代理等级、授权区域、授权产品线、授权有效期、信用额度、负责人。  
**功能**：维护授权范围、代理价规则、查看下属终端客户和历史报价。  
**校验**：报价产品或销售区域超出授权范围时阻止提交或进入公司特批。

### P44 销售区域

**形式**：国家/大区/省份等树形结构。  
**功能**：新增节点、移动、停用、分配销售组织、关联默认币种和价格表。  
**校验**：存在有效客户或价格规则引用的节点不得直接删除。

### P45 销售组织

**字段**：组织编码、名称、上级组织、负责人、产品线、区域、成员。  
**功能**：树形维护、成员调动、生效日期、数据权限预览。

## 4.5 报价中心

### P50 新建报价——步骤一：基本信息

**字段**：

- 报价日期、有效期；
- 客户、联系人、商机编号；
- 公司、销售组织、销售负责人；
- 国内/国际、销售区域、客户等级、代理等级；
- 报价币种、汇率、含税方式、贸易术语；
- 项目名称、客户需求摘要、预计交期。

**自动带出**：客户的区域、等级、币种、付款条件和销售负责人。  
**校验**：销售只能选择授权客户；客户主数据缺少区域或等级时禁止进入下一步。

### P51 新建报价——步骤二：选择产品

**页面布局**：左侧系列和型号筛选，中间产品卡片，右侧已选产品。

**功能**：

- 按产品线、产品分类、关键词和可检索技术参数搜索；
- 查看产品图片和关键技术参数；
- 选择一个或多个主机、配置包、配件及服务；
- 从推荐配置模板开始；
- 从历史报价复制；
- 显示产品是否适用于当前区域和客户等级。

**校验**：停用、未发布或不适用当前市场的型号不得加入报价。

### P52 新建报价——步骤三：产品配置器

**页面布局**：

- 左侧：产品配置组导航和完成状态；
- 中间：当前配置组的选项卡片；
- 右侧：已选配置、价格变化和规则消息；
- 底部：上一步、保存草稿、验证配置、下一步。

**功能**：

- 单选、多选、数量和参数输入；
- 根据条件动态显示或隐藏选项；
- 自动选中依赖项；
- 禁用互斥选项并说明原因；
- 显示必选项和未完成项；
- 实时计算价格、重量、数量和预计交期；
- 显示错误、警告和建议；
- 一键恢复默认配置；
- 保存为个人配置草稿；
- 查看配置差异。

**服务端校验**：前端规则只用于交互，点击保存、试算、提交时必须由后端使用同一规则版本重新计算。  
**输出**：合法配置 JSON、规则版本、配置摘要、配置 BOM、配置指纹哈希。

### P53 新建报价——步骤四：价格与折扣

**行项目字段**：产品/配置、数量、目录价、指导价、报价单价、折扣率、税率、小计、价格校验结果。  
**整单字段**：产品金额、服务费、运费、保险费、折扣、税额、报价总额、毛利等级。

**功能**：

- 自动匹配价格表和价格规则；
- 输入报价单价或折扣率，另一个字段反算；
- 查看面向销售公开的价格计算说明；
- 特价时填写原因、竞争对手、附件；
- 重新试算；
- 对不同配置方案进行并排比较。

**三级控制规则**：

| 实际报价 | 校验结果 | 系统动作 |
| --- | --- | --- |
| `>= 官方指导价` | 正常 | 可直接进入销售确认 |
| `< 指导价` 且 `>= 产线控制价` | 需产线审批 | 提交产线价格审批 |
| `< 产线控制价` 且 `>= 公司控制价` | 需公司审批 | 必填特价原因并提交公司审批 |
| `< 公司控制价` | 禁止报价 | 阻止提交，不允许 API 绕过 |
| 缺少价格策略 | 禁止报价 | 显示缺失的型号/选项和维度 |

**整单规则**：以所有行项目中最严格的审批等级为整单审批等级。

### P54 新建报价——步骤五：商务条款

**字段**：付款条件、交货期、交货地点、贸易术语、质保期、安装调试、培训、验收标准、报价有效期、特殊条款。  
**功能**：从报价条款模板选择、按国内/国际自动推荐、允许填写偏差说明、上传附件。  
**校验**：偏离标准付款、质保或责任条款时，标记报价条款偏差并按报价审批规则升级。

### P55 新建报价——步骤六：预览与提交

**页面内容**：客户信息、配置摘要、技术参数、BOM 摘要、价格明细、商务条款、审批路径、PDF 预览。

**功能**：

- 完整性检查；
- 最终配置校验和价格重算；
- 查看即将冻结的产品规则和价格版本；
- 生成临时报价 PDF；
- 返回指定步骤修改；
- 提交审批。

**提交校验**：

- 客户、产品、配置、价格和条款完整；
- 配置无阻断错误；
- 每行价格策略匹配成功；
- 价格不低于公司控制价；
- 特价理由和附件符合规则；
- 提交人有客户和产品线数据权限。

### P56 报价列表

**列表字段**：报价单号、版本、客户、项目、产品线、币种、金额、价格等级、审批状态、客户状态、有效期、销售负责人、更新时间。  
**筛选**：关键词、日期、客户、区域、产品线、报价状态、审批状态、价格风险、销售人员。  
**操作**：新建、复制、创建修订、导出、打印、发送、标记客户接受/拒绝、作废。  
**视图**：我的报价、团队报价、待处理、即将过期、公司特批、全部。

### P57 报价详情

**顶部信息**：单号、版本、状态、客户、金额、价格风险、当前审批节点。  
**页签**：报价概览、产品配置、价格明细、商务条款、审批记录、版本差异、附件、操作日志、接口记录。

**操作随状态变化**：

- 草稿：编辑、删除、提交审批；
- 审批中：撤回、催办；
- 驳回：创建修改版本、重新提交；
- 已批准：下载正式 PDF、发送客户、创建修订、记录客户反馈；
- 已过期：复制为新报价；
- 已作废：只读查看。

**限制**：已提交及已批准内容只读；所有修改必须创建新版本。

### P58 报价版本

**列表字段**：报价单号、版本号、来源版本、变更原因、变更人、时间、金额变化、配置变化、状态。  
**功能**：双栏或逐字段差异对比；查看配置、价格、条款和附件变化；恢复内容到新草稿。  
**规则**：每个版本保存完整快照，不依赖当前主数据还原历史内容。

### P59 报价模板

**功能**：维护中英文报价结构、封面、公司信息、产品图片、技术参数、价格表、条款、签章区域。  
**变量**：只允许使用白名单模板变量；模板预览显示缺失变量。  
**操作**：新增、复制、预览、发布、停用、设为不同市场默认模板。

### P60 报价打印记录

**列表字段**：报价单号、版本、模板、语言、生成时间、生成人、文件哈希、下载次数。  
**功能**：下载历史文件、验证哈希、查看发送记录。  
**规则**：正式报价 PDF 一经生成不可覆盖；修订后生成新文件。

## 4.6 审批中心

### P70 我的待审批

**列表字段**：业务单号、客户、产品线、金额、折扣、毛利等级、风险原因、申请人、到达时间、SLA。  
**功能**：进入审批、转交、加签、退回补充资料、催办记录。

### P71 报价审批详情

**页面布局**：

- 顶部：报价摘要和当前审批路径；
- 左侧：配置、价格、条款和附件；
- 右侧：风险项、历史审批、审批操作；
- 下方：版本差异和规则执行轨迹。

**审批动作**：批准、驳回、退回修改、加签、转交。  
**审批字段**：审批意见、原因分类、附件、下一处理人。  
**校验**：审批时重新确认报价版本未变化；如果已变化，终止本任务并要求重新提交。

### P72 我发起的

**功能**：查看当前节点、处理人、停留时间、催办、允许条件下撤回、查看完整流程图。

### P73 审批记录

**列表字段**：业务类型、单号、节点、动作、处理人、代理人、意见、开始/完成时间、处理时长。  
**功能**：按人员、组织、产品线、时间检索并导出；审计角色可查看签名前后数据哈希。

### P74 审批规则

**字段**：规则名称、适用范围、价格等级、审批角色、候选人映射、SLA、启停状态、版本。  
**MVP 功能**：维护固定路径所需的审批角色、候选人、适用产品线和 SLA，支持规则模拟与版本发布；不提供任意节点编排或可视化流程设计器。  
**第一阶段固定路径**：

```text
正常价格 → 销售确认 → 已批准
需产线审批 → 产线价格审批 → 已批准
需公司审批 → 产线审核 → 公司价格审批 → 已批准
低于公司控制价 → 禁止提交
```

### P75 委托与代理

**字段**：委托人、代理人、业务类型、产品线、开始时间、结束时间、原因、状态。  
**功能**：新增、撤销、审批、查看代理操作记录。  
**限制**：代理关系不能突破代理人原有数据权限；创建人与审批人分离规则仍然有效。

## 4.7 报表中心

### P90 报价漏斗

按时间、区域、销售、产品线展示报价数量、金额和状态转化；支持下钻到报价列表。

### P91 折扣与毛利分析

展示指导价差异、折扣率分布、毛利等级、产线审批和公司特批比例。成本和毛利金额只对授权角色显示。

### P92 审批效率

展示节点平均处理时长、超时次数、驳回率、审批人负荷和瓶颈节点。

### P93 产品配置分析

展示型号销售次数、选项选择率、常见配置组合、规则警告频率和配置失败原因。

### P94 报价明细导出

按权限导出报价、行项目、配置、价格和审批信息；导出任务异步执行，文件设有效期并记录下载日志。

## 4.8 系统管理

### P100 用户与角色

基于 FastAdmin 权限体系维护用户、角色、菜单、按钮和数据范围；增加销售组织、产品线和区域授权。

### P101 字典与参数

维护业务板块、产品线、客户等级、代理等级、币种、贸易术语、状态、原因分类等。已被业务引用的字典值只能停用。

### P102 编号规则

维护报价、产品、价格版本等编号格式。示例：`Q-{YYYY}-{SEQ6}`。服务端必须使用数据库锁或序列避免并发重号。

### P103 打印模板

维护模板文件、变量白名单、语言、纸张、页眉页脚、水印和签章；支持测试数据预览和版本发布。

### P104 接口管理

维护 CRM、ERP 等系统的接口地址、凭证、签名方式、超时、重试策略和启停状态。凭证加密保存，页面只能重置不能回显明文。

### P105 异步任务

查看 PDF 生成、Excel 导入导出、ERP 同步、邮件发送等任务；支持查看错误、受控重试和下载错误报告。

### P106 审计日志

**记录内容**：登录、查询敏感价格、查看成本、增删改、导入导出、发布、审批、打印、下载、接口调用。  
**字段**：用户、角色、IP、设备、操作、对象、对象 ID、前后差异、时间、结果、请求追踪号。  
**限制**：业务用户不可修改或删除审计日志；日志按公司安全策略归档。

## 5. 核心业务状态机

### 5.1 产品与规则版本状态

```text
DRAFT（草稿）
  → PENDING_APPROVAL（待审批）
  → PUBLISHED（已发布）
  → EXPIRED（已失效）

PENDING_APPROVAL → DRAFT（驳回）
```

已发布记录不可编辑。任何变更通过“复制新版本”完成。

### 5.2 报价状态

```text
DRAFT → PENDING_SALES_CONFIRM → APPROVED
DRAFT → PENDING_LINE_APPROVAL → APPROVED
DRAFT → PENDING_LINE_APPROVAL → PENDING_COMPANY_APPROVAL → APPROVED
APPROVED → SENT → CUSTOMER_ACCEPTED / CUSTOMER_REJECTED

审批中 → REJECTED / RETURNED / WITHDRAWN
已批准或已发送 → CUSTOMER_REJECTED / EXPIRED / CANCELLED / REVISED
```

报价主状态和审批任务状态分开存储，不允许用一个文本字段同时表达两类状态。

### 6.4 关键数据库约束

- 产品、规则、价格、报价版本均有唯一业务编码或版本唯一索引；
- 所有引用使用外键或在服务层实施等价的完整性校验；
- 报价版本号使用唯一索引 `quote_id + revision_no`；
- 相同适用范围和时间区间的发布版本不得冲突；
- 审批动作插入和任务状态变化必须处于同一数据库事务；
- 软删除只用于草稿或主数据；审批、版本、审计和正式文件不允许业务层删除。

## 7. CPQ 核心服务设计

### 7.1 配置服务 `ConfigurationService`

输入：型号、当前配置、客户/市场上下文、规则版本。  
输出：标准化配置、可见选项、自动选择项、错误、警告、计算属性、配置哈希。

处理顺序：

1. 校验型号和规则版本有效；
2. 标准化输入并移除未知字段；
3. 计算可见性和默认值；
4. 执行依赖、互斥和数量规则；
5. 执行计算公式；
6. 检查必选和完整性；
7. 生成 BOM；
8. 输出稳定排序后的配置 JSON 和 SHA-256 哈希。

### 7.2 价格服务 `PricingService`

建议固定执行顺序：

```text
型号基础价
+ 选项增量价
+ 配件/服务价
→ 适用价格规则
→ 数量调整
→ 客户/代理/区域调整
→ 手工折扣
+ 运费/保险/安装等费用
→ 未税金额
+ 税额
→ 含税总额
→ 汇率换算与金额舍入
→ 三层控制价比较
→ 审批等级
```

每一步都写入 `price_trace_json`，内容包括输入金额、命中规则、调整值、输出金额和规则版本。

### 7.3 价格策略匹配优先级

从最具体到最通用匹配：

1. 指定客户；
2. 指定代理商；
3. 客户/代理等级 + 区域；
4. 客户/代理等级；
5. 区域；
6. 国内/国际；
7. 产品线默认；
8. 公司默认。

相同具体程度时取优先级更高的规则；仍冲突时不进行猜测，返回“规则冲突”并阻止报价提交。

### 7.4 审批服务 `ApprovalService`

职责：计算审批路径、创建任务、校验审批权限、执行状态迁移、处理撤回/退回/加签/委托并写入日志。  
要求：服务端状态机白名单；所有动作携带报价版本号和幂等键；旧版本任务自动失效。

### 7.5 报价版本服务 `QuoteRevisionService`

职责：创建草稿、复制报价、创建修订、冻结快照、生成版本差异。  
快照必须包含客户销售属性、产品配置、BOM、价格执行轨迹、汇率、税费、条款、规则版本和模板版本。

### 7.6 PDF 服务 `QuoteDocumentService`

职责：根据冻结快照生成 PDF，支持中文/英文和不同市场模板；生成文件哈希并保留历史文件。  
PDF 任务异步执行，失败可重试但不能覆盖已成功的正式文件。

## 8. API 设计

统一前缀：`/api/cpq/v1`。通过 `application/route.php` 显式注册 CPQ 路由，Controller 继续调用 FastAdmin `Api::success()` / `Api::error()`，不修改框架响应基类。响应保持现有 `code`、`msg`、`time`、`data` 外壳，业务错误码和追踪号放入 `data`：

```json
{
  "code": 1,
  "msg": "OK",
  "time": 1788400000,
  "data": {
    "business_code": "OK",
    "trace_id": "01J...",
    "payload": {}
  }
}
```

### 8.1 关键接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/product-models` | 查询可售型号 |
| GET | `/product-models/{id}/schema` | 获取配置结构和有效规则版本 |
| POST | `/configurations/validate` | 校验配置并返回规则结果 |
| POST | `/configurations/bom` | 生成模拟 BOM |
| POST | `/prices/calculate` | 确定性价格试算 |
| POST | `/prices/explain` | 返回授权范围内的价格轨迹 |
| GET | `/quotes` | 报价列表 |
| POST | `/quotes` | 新建报价草稿 |
| GET | `/quotes/{id}` | 报价详情 |
| PUT | `/quotes/{id}/draft` | 修改草稿 |
| POST | `/quotes/{id}/revisions` | 创建修订版本 |
| POST | `/quotes/{id}/submit` | 最终重算并提交审批 |
| POST | `/quotes/{id}/withdraw` | 撤回审批 |
| POST | `/quotes/{id}/documents` | 生成报价 PDF |
| GET | `/approval-tasks` | 我的审批任务 |
| POST | `/approval-tasks/{id}/actions` | 执行审批动作 |
| POST | `/imports/{type}` | 创建导入任务 |
| GET | `/jobs/{id}` | 查询异步任务 |

### 8.2 API 强制要求

- 所有写接口校验 CSRF 或 API 签名；
- 对外接口使用 OAuth2、访问令牌或 HMAC，不使用永久明文密码；
- `submit`、审批动作、正式文件生成等接口要求 `Idempotency-Key`；
- 金额以字符串形式传输，避免前端浮点误差；
- 接口校验乐观锁版本号，冲突返回 `409`；
- 敏感价格字段根据角色从响应中移除；
- 所有错误在 `data.business_code` 中返回稳定错误码，例如 `CPQ_CONFIG_INVALID`、`CPQ_PRICE_POLICY_MISSING`、`CPQ_BELOW_COMPANY_FLOOR`，并设置正确 HTTP 状态码；
- 日志禁止记录访问令牌、密码和完整个人敏感信息。

## 9. FastAdmin 工程结构

禁止直接修改 FastAdmin 和 ThinkPHP 框架核心。以下结构与当前仓库的后台 Controller/Model/Validate/View、API Controller 和 RequireJS 模块保持一致：

```text
application/
├── admin/
│   ├── controller/cpq/       # 后台页面控制器，只做参数接收和响应
│   ├── model/cpq/            # ORM 模型
│   ├── validate/cpq/         # 输入验证
│   ├── view/cpq/             # FastAdmin后台视图
│   └── lang/zh-cn/cpq/       # 中文语言文件
├── api/
│   └── controller/cpq/       # CPQ API 控制器
└── common/
    ├── service/cpq/          # 配置、定价、审批、版本等核心服务
    ├── library/cpq/          # 值对象、规则解释器和状态机
    ├── exception/cpq/        # 业务异常
    └── job/cpq/              # PDF、导入导出、同步任务

public/assets/js/backend/cpq/ # 与控制器路径一致的RequireJS页面模块
database/cpq/
├── install.sql               # CPQ首次安装脚本
├── upgrades/                 # 按版本递增的升级SQL
└── demo.sql                  # 可选演示数据，不含真实商业数据
tests/
└── cpq/                      # 规则、价格、API、权限和状态机测试
```

### 9.1 分层规则

- 后台 Controller 继承现有 `app\common\controller\Backend`，列表和单表 CRUD 优先复用 `Backend` trait；
- API Controller 继承现有 `app\common\controller\Api`，继续使用框架认证、响应和异常处理约定；
- Controller 不写价格计算、规则判断和审批状态逻辑；
- Model 不承担跨表业务流程；
- 核心逻辑全部放入可单元测试的 Service/Library；
- 后台列表使用 Bootstrap Table，表单使用 FastAdmin Form，页面脚本使用 RequireJS `define(...)`；
- 不在 MVP 中新增 Vue、React、Node 服务或另一套前端路由；
- 数据库安装与升级 SQL 进入版本控制，禁止直接修改 `application/admin/command/Install/fastadmin.sql`，也禁止只提交手工 SQL 截图；
- 后端计算是最终结果，前端只负责展示和交互；
- 配置规则和价格规则都使用受控 DSL，不执行用户输入代码；
- 金额统一封装 Money/Decimal 值对象；
- 日期统一保存 UTC，页面按 Asia/Shanghai 显示；
- 新增和修改的源代码注释默认使用中文。

### 9.2 技术栈准入门槛

正式开发前必须基于当前仓库的 FastAdmin `1.6.5.20260602`、ThinkPHP `5.0.28` 和 Composer 依赖执行兼容性 PoC，确认 PHP、MySQL、Redis、队列、PDF 与 Excel 组件的可运行组合，并锁定 `composer.lock`。如果当前组合存在无法接受且无法修复的安全风险，应先形成升级 ADR，经确认后再升级，不允许开发过程中临时替换框架或另建技术栈。

   ↓ HTTPS

### 10.1 容器建议

- `app`：FastAdmin/PHP-FPM；
- `worker`：队列任务；
- `mysql`：业务数据库；

- `scheduler`：定时发布、报价过期、同步重试；

- `dev`：开发人员本机；
- `test`：集成测试和业务验收；
- `prod`：正式环境。

三个环境使用不同数据库、密钥、域名和对象存储。禁止用生产客户和真实价格数据直接填充开发环境。

### 10.3 运维要求

- 数据库每日全量备份和增量备份；
- 报价 PDF、附件、环境配置密钥分别备份；
- 每季度执行恢复演练；
- 正式环境只开放 80/443 和受限运维端口；
- 管理员启用强密码和多因素认证；
- 系统、PHP、数据库和依赖建立安全更新机制；
- 关键发布前自动备份，数据库迁移必须可前滚或有恢复方案。

## 11. 非功能需求

### 11.1 性能

- 常规列表首屏响应不超过 2 秒；
- 单个产品实例的配置规则校验不超过 500 毫秒；
- 单份 100 行以内报价试算不超过 2 秒；
- PDF 生成采用异步任务，普通报价 30 秒内完成；
- 导入导出超过 5,000 行必须异步处理。

### 11.2 安全

- 服务端权限、数据范围、状态机和价格底线四重校验；
- 防止 SQL 注入、XSS、CSRF、越权和不安全文件上传；
- 上传文件按白名单校验扩展名、MIME、大小并病毒扫描；
- 控制价、成本和凭证字段加密或脱敏；
- 正式报价和审批动作保存内容哈希；
- 审计日志防业务用户删除。

### 11.3 可用性与可维护性

- 所有核心计算提供“解释结果”，便于业务验证；
- 规则、价格和审批流程均版本化；
- 错误信息必须指出具体型号、配置项或价格维度；
- 数据导入先预览、再确认，错误行可下载；
- 核心服务单元测试覆盖率目标不低于 80%；
- 金额边界、权限和状态迁移必须 100% 覆盖关键路径。

- `CPQ-DEMO-AGENT-01`：一级代理、华东、国内、CNY；
- `CPQ-DEMO-CUSTOMER-02`：战略客户、华南、国内、CNY；
- `CPQ-DEMO-AGENT-02`：一级代理、东南亚、国际、USD。

### 12.3 核心报价验收场景

| 用例 | 场景 | 预期结果 |
| --- | --- | --- |
| `Q-001` | 报价等于或高于指导价 | 正常，可批准 |
| `Q-002` | 低于指导价但不低于产线控制价 | 必须进入产线审批 |
| `Q-003` | 低于产线控制价但不低于公司控制价 | 必须填写理由并进入公司审批 |
| `Q-004` | 低于公司控制价 | 前端和 API 均阻止提交 |
| `Q-005` | 国际客户、USD 价格表 | 使用有效汇率快照，进入正确审批层级 |
| `Q-006` | 缺少指定区域价格策略 | 阻止提交并指出缺失维度 |
| `Q-007` | 多行报价包含不同风险等级 | 整单取最严格审批等级 |
| `Q-008` | 价格发布后打开历史报价 | 历史报价金额和轨迹不变化 |
| `Q-009` | 审批过程中修改报价 | 原任务失效，必须提交新版本 |
| `Q-010` | 已批准报价修订 | 创建新版本，旧版保持只读 |

### 12.4 配置规则验收场景

| 用例 | 场景 | 预期结果 |
| --- | --- | --- |
| `C-001` | 必选项未选择 | 阻止进入价格步骤并定位配置组 |
| `C-002` | 选择依赖项 | 自动选择或要求选择被依赖项 |
| `C-003` | 选择互斥项 | 禁用冲突项并说明规则来源 |
| `C-004` | 数量超过上限 | 阻止保存并显示允许范围 |
| `C-005` | 新规则形成循环依赖 | 规则发布失败 |
| `C-006` | 配置规则版本更新 | 历史报价仍可按旧快照还原 |
| `C-007` | 前端绕过规则直接调用 API | 服务端拒绝非法配置 |

### 12.5 权限与审计验收

- 销售不能通过列表、详情、导出或 API 获取成本和公司控制价；
- 华东销售不能查看无授权的其他区域报价；
- 产线审批人只能审批授权产品线；
- 报价人不能批准自己的公司级特价；
- 每次查看敏感价格、导出和正式 PDF 下载均产生审计记录；
- 删除前端按钮或篡改请求不能绕过服务端权限。

## 13. 分阶段开发计划

### M0 技术验证与项目基线（第 1 周）

- 单元测试覆盖依赖、互斥、必选和数量规则。

- 价格模拟器；

### M3 报价审批、打印与审计（第 6～7 周）

### M4 验收与上线准备（第 8 周）

## 14. AI 辅助开发执行规范

### 14.1 AI 开发的上下文文件

仓库根目录应维护：

- `AGENTS.md`：工程规范、中文注释要求、禁止事项；
- `docs/cpq/domain.md`：业务术语和规则；
- `docs/cpq/pages.md`：本文页面规格的仓库版；
- `docs/cpq/data-model.md`：数据表和字段；
- `docs/cpq/openapi.yaml`：API 契约；
- `docs/cpq/state-machines.md`：状态机；
- `docs/cpq/acceptance-tests.md`：验收用例；
- `docs/adr/`：关键架构决策记录。

AI 每次开发前必须读取相关文件，不能只根据单条自然语言需求修改系统。

### 14.2 AI 每次任务的最小闭环

```text
理解一个页面或一条业务能力
→ 核对数据模型和 API 契约
→ 编写或更新数据库安装/升级 SQL
→ 实现服务层与权限校验
→ 实现 API
→ 实现页面
→ 添加测试数据
→ 编写单元/接口/权限测试
→ 运行格式化、静态检查和测试
→ 更新文档
```

一次任务只完成一个可验收的功能，不让 AI 同时重构框架、升级依赖和开发业务页面。

### 14.3 给 AI 的任务模板

```markdown
## 任务
实现页面 Pxx：<页面名称>。

## 业务目标
<用户为什么需要该页面>。

## 允许修改范围
- application/...
- public/assets/...
- tests/...
- database/cpq/...

## 必须实现
1. 字段、筛选、按钮；
2. 服务端权限与数据范围；
3. 业务校验；
4. API 契约；
5. 审计日志；
6. 单元测试和接口测试。

## 禁止事项
- 不修改 FastAdmin 核心；
- 不使用 eval 执行规则；
- 不使用 float 计算金额；
- 不只做前端校验；
- 不覆盖已发布版本和历史报价；
- 不在日志中输出密钥或敏感价格。

## 验收条件
- Given ... When ... Then ...；
- 运行命令 ... 全部通过；
- 页面截图和 API 示例符合规格。
```

### 14.4 AI 开发示例任务拆分

错误任务：

> 帮我把整个 CPQ 做出来。

正确拆分：

1. 建立产品系列和产品型号安装/升级 SQL、模型、CRUD、权限及测试；
2. 建立配置组和选项的数据结构、接口和后台页面；
3. 定义配置规则 JSON Schema，完成解析和 Schema 校验；
4. 实现 `REQUIRES` 单规则及单元测试；
5. 实现 `EXCLUDES`、`ONE_OF`、`MIN_MAX` 规则；
6. 实现规则冲突和循环依赖检测；
7. 完成配置器只读 Schema API；
8. 完成配置器交互和服务端二次校验；
9. 建立价格表和价格条目；
10. 实现确定性价格流水线和执行轨迹；
11. 实现三层控制价边界测试；
12. 最后组装六步报价向导。

### 14.5 AI 代码审查清单

- 是否把业务逻辑写进 Controller 或 JavaScript；
- 是否存在前端通过、后端未校验的路径；
- 是否使用浮点数计算金额；
- 是否允许修改已发布规则、价格或报价快照；
- 是否存在越权查询和批量导出风险；
- 是否使用 `eval` 或动态 SQL；
- 是否正确处理并发提交、重复审批和接口重试；
- 是否在一个事务内完成状态迁移和日志；
- 是否生成数据库升级、回滚或恢复说明；
- 是否覆盖正常、边界、异常和越权测试；
- 是否包含不必要的框架核心修改或无关重构。

## 15. 完成定义（Definition of Done）

一个页面或功能只有同时满足以下条件才算完成：

1. 页面字段、按钮、状态和提示符合本规格；
2. 服务端权限与数据范围验证完成；
3. 数据库安装/升级 SQL 可在空库和已有测试库执行，并有回滚或恢复说明；
4. 核心业务逻辑位于服务层且可测试；
5. 单元测试、API 测试、权限测试全部通过；
6. 金额、日期、并发和错误分支经过验证；
7. 关键操作写入审计日志；
8. API 文档、页面说明和变更记录同步更新；
9. 未修改 FastAdmin 核心文件；
10. 测试环境完成产品负责人验收。

## 16. 项目启动前需要业务确认的事项

1. 首批试点产品的通用结构：系列、型号、参数模板、配置组、选项、配件/服务和 BOM 的真实层级；
2. 每条产品配置规则的业务负责人和生效范围；
3. 官方指导价、产线控制价、公司控制价是否按行还是整单判断；
4. 低于公司控制价是绝对禁止，还是增加总经理特批；
5. 价格维度优先级以及客户专属价与代理价的冲突处理；
6. 运费、税费和汇率是否参与价格底线与毛利计算；
7. 国内和国际报价单模板及中英文内容；
8. 销售、产品线价格、公司价格和财务审批人员及代理规则；
9. CRM、ERP 的接口边界和主数据归属；
10. 报价、附件、正式 PDF 和审计日志的保留年限。

## 17. 推荐实施决策

本项目已经采用 FastAdmin 代码基线，MVP 不再进行框架选型。第一阶段先固化通用产品配置、价格计算、三级控制价、报价版本、报价审批和 PDF 六项核心能力，所有页面与接口按当前 FastAdmin 工程约定增量开发。

M0 必须先解决运行时兼容性、依赖锁定和测试基线；后续如需升级 ThinkPHP、替换配置器前端或拆分服务，应单独形成 ADR 和迁移计划，不与 MVP 业务开发混合实施。合同能力需在本次 MVP 验收后独立立项，不预建合同页面、数据表、状态机或 API。
